# Authentication: Day 0.7.1 capability map

Checked against the app's pinned `day-app` / `day-pieces` / `day-toolkit-uikit` 0.7.1 source and the current auth implementation. Current online Day docs are a secondary reference; the pinned source determines availability.

| Behavior in auth | Day 0.7.1 support | Migration decision |
|---|---|---|
| Username/password/new-password role, keyboard purpose, correction defaults, submit-key label | `TextField::input_purpose`, `submit_label`; UIKit renderer maps these to native text traits. Already used by login. | Keep declarative Day configuration. Remove duplicate setters only after checking they do not provide additional behavior. |
| Secure entry and show/hide password on one field | `TextField::secure` is reactive and documents preserving value/focus across backends. Already used. | Keep Day API; retain coverage that masking uses the same field/value. |
| Focus binding | `Decorate::focused` exists. | Keep Day focus state. Audit transition timing separately; public focus binding does not itself prove the app can preserve its current navigation/keyboard handoff behavior. |
| Native toolbar/menu and localized labels | Day `toolbar_menu`, toolbar entries and `IntoText` are available; already used. | Keep declarative toolbar. Remove native title hooks only after verifying Day's route title updates when locale changes. |
| Reusable form/page layout, vector tint, button styling, visibility animation | Day Pieces/modifiers and reactive bindings are available. | Express composition and supported animation declaratively; no UIKit needed for these cases. |
| Native authentication traits repaired after input-mode changes | No declarative/cross-platform Day API conditionally reads or repairs traits on an active field. Day exposes a UIKit-specific `uikit`/`with_native` hook, but does not manage ongoing repair. | Capability gap. Do not remove trait reconciliation without accepting changed behavior or a separately approved Day API/extension. |
| Password rules, explicit native value synchronization, return-key delegate proxy | No declarative/cross-platform Day API found. Day exposes a UIKit-specific `uikit`/`with_native` hook, which can host app-owned behavior but does not make it portable or Day-managed. | Capability gap. These are not covered by `input_purpose`; preserve until product chooses native default behavior or an extension. |
| Transition-aware focus with route/top-controller/cancellation guards | Day `focused` binding exists; no matching public transition-coordinator contract found in the audited API. | Capability gap; investigate whether default Day navigation now meets the required interaction before retiring the UIKit coordination. |
| Keyboard frame tracking, safe-area-aware dock translation, first-responder dismissal, control-aware outside-tap handling | Day has a `.keyboard()` interaction modifier, but it is for keyboard input to a piece; no public keyboard geometry/dock/focus-dismissal service matching these app behaviors was found. | Capability gap; `.keyboard()` is not a replacement for the current keyboard observer/follower. Do not substitute it by name alone. |
| Password capture input and invisibility/clipping | Day supports opacity, visibility, sizing and interaction modifiers, but no verified contract found for reproducing the current UIKit accessibility/touch clipping behavior of the one-point capture field. | Audit native accessibility and hit testing before replacement. Do not claim visual hiding alone is equivalent. |
| Authentication diagnostics | Existing diagnostics intentionally read trait snapshots without credentials. No equivalent cross-platform Day diagnostic API found; the UIKit hook can provide app-owned diagnostics. | Keep diagnostics until an explicit replacement is designed; it may remain a scoped platform diagnostic if the user approves that exception. |
| Welcome/credential content and Lottie stickers | Day layout primitives and the existing Lottie piece cover these. | Already Day-native; split files without rewriting behavior. |

## Conclusion

Day 0.7.1 already owns the primary input-purpose, secure-mask, focus-binding, toolbar and layout contracts. The remaining UIKit code implements behaviors beyond those builder APIs: active trait repair, password rules/value synchronization, delegate forwarding, transition-aware focus, keyboard geometry/followers, outside-tap policy and diagnostics. A strict removal of all app-owned platform code cannot currently be promised while preserving those behaviors. The first safe slice is to split auth composition/flow and remove only proven duplication. For each capability gap, ask for a focused product choice before changing runtime behavior or introducing a Day extension.
